This record describes the prepared `0.9.0` candidate. It is deliberately not
a publication record: no `v0.9.0` tag or GitHub Release exists as part of this
task, and Stable remains `v0.8.2` until owner OPS03 Preview/UAT passes.

## Candidate boundary

The candidate contains accepted work integrated after `v0.8.2`: Decision
Support v1 and Scenario Lab, Performance v1 and bounded PERF04 decomposition,
linked-financing integrity, AI financial-review/export hardening, OPS01
Prepare + deterministic Start, OPS02 explicit immutable Stable update, OPS03
exact-SHA isolated Preview/UAT preparation, and release-confidence CI changes.

UI v2 is a separate workstream and is not part of this release. No financial
formula, provider, runtime-data or network behavior is introduced by this
release-prep task; no migration is added, and the canonical Alembic head stays
`0041_debt_linked_account`.

## Version identity

The prepared application identity is `0.9.0` across backend package metadata
and `__version__`, generated `backend/uv.lock`, frontend package metadata and
lockfile, `/api/health` expectations, Windows launcher source/config/example
and current-release safety assertions, release-verification assertions and
current release documentation. Published Stable references remain `v0.8.2`
where they describe the actually published or installed runtime and its owner
transition baseline.

## Owner gate and publication boundary

After integration, record one exact canonical candidate SHA and pin OPS03
Preview/UAT to that SHA with isolated UAT data. An owner `PASS` permits the
guarded #124 publication flow. Only after publication should OPS02 perform
the first real release-to-release transition `v0.8.2 -> v0.9.0`.

No owner UAT, OPS02 operation, tag, GitHub Release, `/release` trigger or
private runtime access is part of this preparation task.
