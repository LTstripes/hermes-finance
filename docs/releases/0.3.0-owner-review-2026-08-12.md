Текущая таблица перегружена колонками и actions.

# R03-16. Passive-income average eligibility contract

**Priority:** P0  
**Status:** READY  
**Owner/executor:** Лера  
**Implementation:** отсутствует — contract/docs only  
**Depends on:** existing accepted C03 / `MASTER_SPEC §10.5`

## Проблема

Текущий accepted contract считает фактическое среднее по CLOSED reporting months: пока месяцев меньше 12 — по всем доступным CLOSED месяцам; после накопления 12 — rolling window последних 12 reporting months. Это **не calendar-year average**.

Следствие: исторический CLOSED месяц с нулевым passive income считается настоящим нулём. Это правильно для реального месяца без выплат, но искажает owner metric, если ранние reporting months были заведены только ради salary/tax history и не содержат полноценной инвестиционной истории.

Автоматически исключать все zero-income months нельзя: настоящий месяц с нулевым passive income должен оставаться в среднем.

## Предпочтительное product direction для contract task

Зафиксировать explicit eligibility boundary, а не произвольную ручную выборку каждого месяца:

- настройка уровня приложения/аналитики **«Учитывать пассивный доход начиная с …»**;
- CLOSED months до выбранной границы не входят в passive-income rolling average;
- после границы каждый eligible CLOSED month входит, включая настоящий ноль;
- draft/reopened months по-прежнему не входят;
- окно остаётся rolling максимум 12 **eligible CLOSED months**, не calendar year;
- UI явно показывает `N из 12` и период, который реально участвует в расчёте;
- default/migration semantics для существующих установок должны быть backward-safe и не молча менять результат до выбора/принятого default;
- влияние этой eligibility boundary на passive-income Goal current value и dividend component forecast должно быть определено одним source of truth, а не разными фильтрами.

Допустим другой contract только если он лучше решает различие «неполная историческая запись» vs «реальный нулевой месяц» без ручного микроменеджмента.

## Acceptance

- обновлён `MASTER_SPEC §10.5` и при необходимости отдельный ADR;
- однозначно определены default, migration/backward compatibility, CLOSED/reopen behavior и rolling-window selection;
- синтетические примеры покрывают: excluded historical month, eligible zero month, <12 eligible months, >12 eligible months, gap/draft/reopen;
- отдельно зафиксировано влияние на Goals и forecast dividend component;
- никакой implementation в этой task-card.
