## 0. Назначение и границы релиза

`0.4.0` добавляет первую внешнюю read-only интеграцию: обновление рыночных котировок поддерживаемых инструментов по явному действию владельца.

Primary technical provider — MOEX ISS, но production activation зависит от data-usage gate из ADR 0009. Архитектура provider adapter должна позволять заменить источник, если условия MOEX не подходят для intended local automated use.

Релиз сознательно ограничен котировками и provenance. Он не превращается в торговую систему, фоновый синхронизатор, FX engine или универсальный market-data layer.

### В scope

- явная board-aware market identity для поддерживаемых MOEX instruments;
- `stock`, `fund`, `bond` с RUB-compatible quote semantics;
- получение котировки только по явному запросу пользователя;
- target-date/as-of semantics для monthly snapshot;
- preview `текущее значение → предложенное значение` до применения;
- корректная конверсия bond `% of face` → RUB per unit;
- дата котировки и immutable apply provenance;
- partial success / unavailable / stale / ambiguous mapping states;
- явное исключение инструмента из внешнего обновления;
- manual fallback для замороженных/иностранных/неподдерживаемых активов;
- explicit selective apply;
- tests + Windows/network failure smoke + exact candidate CI.

### Не в scope

- фоновые запросы/cron/daemon refresh;
- торговые операции;
- broker API / banking API;
- FX conversion;
- автоматическое обновление НКД;
- автоматическое изменение закрытых месяцев;
- expected cash-flow generation / купонно-дивидендный календарь (`0.5` candidate);
- импорт PDF Альфа;
- cloud/auth/telemetry/VPS/multi-user;
- изменение финансовых формул.

### Неподвижные инварианты

- приложение остаётся local-only и слушает только `127.0.0.1:8000`;
- внешний источник read-only;
- никаких сетевых запросов без явного действия пользователя;
- полученная извне цена никогда не применяется молча;
- frontend не становится source of truth финансовых вычислений;
- closed month immutable до explicit reopen;
- manual price остаётся первым классом workflow;
- money conversion использует exact decimal + `ROUND_HALF_UP`, не binary float arithmetic;
- private DB/seed/exports/backups/реальные payload не попадают в Git/CI/logs.

## 1. Branching и параллельная поддержка

До выпуска `0.4.0` существуют две линии.

### `main` — стабильная линия `0.3.x`

- latest accepted/releasable current product;
- owner-found bugs, visual fixes и небольшие general improvements делаются fix-ветками от актуального `main`;
- после `v0.3.0` такие изменения при необходимости выпускаются как `0.3.1`, `0.3.2`, ...;
- R04 market-data code в `main` до финала 0.4 не попадает.

### `r04` — integration line будущего `0.4.0`

- создана от exact green baseline `b385e8cddfaa8e057dc34dc73a11d0bc839978d1`;
- каждая implementation task работает в отдельной task branch от актуального `r04`;
- accepted task merge идёт в `r04`, не в `main`;
- task branch не merge/push в другие refs самостоятельно.

### Forward-port stable fixes

Если дефект существует и в stable line, и в `r04`:

1. fix + acceptance сначала в `main`;
2. patch release `0.3.x` при необходимости;
3. затем merge latest accepted `main → r04`;
4. сохранить и stable fix, и уже accepted R04 scope;
5. relevant tests/CI на новом `r04` HEAD.

Одинаковый fix независимо в обеих линиях без причины не дублируем.

Если дефект существует только в R04-коде, он исправляется только в R04 task/fix branch.

### Финал 0.4

1. latest accepted `main` синхронизируется в `r04`;
2. R04 release gate выполняется на exact `r04` candidate HEAD;
3. только после explicit owner release command accepted `r04` интегрируется в `main`;
4. final exact-main CI green;
5. только затем tag `v0.4.0` + GitHub Release.

# R04-02. Read-only market-data provider client

**Priority:** P1  
**Status:** READY

## Scope

Implement the isolated read-only provider boundary defined by ADR 0009.

Primary adapter name may be `moex_iss`, but the normalized domain DTO must not couple future consumers to MOEX response shapes.

Required logical operations:

```text
discover_candidates(query / secid / isin) -> candidate identities
fetch_quote(identity, target_date) -> normalized quote result
```

### Must do

- isolated backend external-client module/boundary;
- bounded connection/read/total timeouts;
- bounded request/concurrency behavior;
- deterministic ISS `columns + data` parsing by column name, never positional magic scattered through services;
- current-day `LAST` path + latest valid historical result `<= target_date` fallback;
- maximum historical lookback 30 calendar days;
- freshness classification exactly per ADR 0009;
- stock/fund exact RUB-per-unit normalization;
- bond `QUOTEBASIS=F` + `FACEVALUE` conversion to RUB per unit;
- bond `QUOTEBASIS=R` cash-per-unit path;
- ISIN candidate mismatch rejection;
- board ambiguity preserved, never auto-resolved as truth;
- normalized statuses/errors: `ok`, `stale`, `unmapped`, `excluded`, `unsupported`, `ambiguous`, `unavailable`, `network_error`, `malformed_response` as applicable at this layer;
- external monetary arithmetic via decimal text/`Decimal`; no binary-float financial calculation;
- synthetic/public non-personal fixtures;
- optional live probe only behind explicit developer invocation; CI must not require network or MOEX availability.

### Must not do

- no DB migration or DB writes;
- no mapping persistence;
- no FastAPI application endpoint yet;
- no frontend/UI;
- no position snapshot mutation;
- no automatic NКД update;
- no FX conversion;
- no background/startup refresh/retry daemon;
- no release claim that live MOEX automation is usage-authorized.

### Regression matrix

At minimum cover ADR 0009 §15:

- stock;
- fund;
- bond percent-of-face;
- bond cash basis;
- missing current LAST → prior result;
- usable previous-trade gap;
- stale 8..30 days;
- unavailable >30/no result;
- ISIN mismatch;
- ambiguous boards;
- unsupported/non-RUB;
- malformed/non-positive quote;
- timeout/network failure;
- partial results preserve successes.

### Verification

- targeted backend tests for provider/parser;
- backend full suite once stabilized;
- Ruff check + format;
- `git diff --check`;
- no secrets/private payloads;
- normal task branch from current `r04`, push branch only, no merge.

### Completion report

Return:

- branch;
- exact remote HEAD;
- files changed;
- adapter/DTO/error model summary;
- exact tests/checks;
- any deviations from ADR 0009;
- explicit confirmation: no DB writes/migration/API/UI/background fetch;
- STOP.
