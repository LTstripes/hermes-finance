## 0. Назначение и актуальная архитектура

`0.4.0` добавляет owner-triggered обновление рыночных котировок поддерживаемых инструментов с обязательным preview до применения.

**Production market-data provider для 0.4 — T-Invest API** через read-only token. Direct MOEX ISS остаётся reference/technical adapter и не является production fallback. Решение зафиксировано ADR 0010.

Каноническая market identity provider-neutral:

```text
provider + provider_instrument_id + optional provider_venue_id
```

Для T-Invest canonical provider key — `instrument_uid`; FIGI не является canonical identity. MOEX-specific `engine / market / boardid / secid` изолированы за MOEX codec.

Релиз остаётся local-only, single-user, Windows-first. Никакого cloud/auth/telemetry, background refresh или trading API.

### Неподвижные инварианты

- runtime слушает только loopback; canonical production address — `127.0.0.1:8000`;
- внешний market provider read-only;
- network access только после явного действия владельца;
- никакого silent provider fallback;
- внешняя цена сначала показывается в preview и никогда не применяется молча;
- frontend не является financial source of truth;
- closed month immutable до explicit reopen;
- mapping reference data не переписывает historical snapshots;
- `Decimal` / integer kopecks + `ROUND_HALF_UP`; никакой binary-float financial arithmetic;
- automatic NKD/FX conversion вне scope;
- private DB/seed/exports/backups/tokens/owner payloads не попадают в Git, CI или logs.

# R04-05C. T-Invest mapping integrity hardening

**Priority:** P0  
**Status:** DONE

## Why

Current T-Invest mapping can persist `provider + instrument_uid` without mandatory provider verification and without carrying candidate ISIN. This is acceptable for read-only preview but is not strong enough before an external quote may mutate a monthly snapshot.

## Scope

- when discovery provides candidate ISIN, preserve it through the save request and hard-reject mismatch with local Instrument ISIN;
- if owner manually enters `instrument_uid` and local Instrument has ISIN but candidate ISIN is not available, accepted mapping must be provider-verified before persistence;
- T-Invest UI save path must use the safe verification contract rather than silently accepting local-only UID;
- malformed one candidate must not discard already valid discovery candidates when partial success is safe;
- preserve explicit owner choice; no auto-map;
- add negative tests for wrong UID/ISIN and verification failures;
- add complete mocked/injected `T-Invest mapping → quote preview` happy path.

## Must not do

- no snapshot mutation/apply/provenance;
- no background/startup network;
- no MOEX production fallback;
- no trading/order/account/transfer APIs;
- no real owner financial data in tests/logs.

## Acceptance

Accepted in `r04-05c-grok` @ `9c8b4bba2f58e79d6b5f012e5cade99393dbacae`; integrated into `r04` via merge `169079b7c1bebe95bf8cee3f12a2a58d36d3c1a4`. A T-Invest identity conflicting with a known local ISIN cannot become an accepted mapping, and a manual UID cannot bypass the required verification path before R04-06. Issue #28 closed after accepting review.

# R04-06. Explicit selective apply + immutable provenance

**Priority:** P0  
**Status:** BLOCKED by R04-05D

R04-06 may start only after mapping integrity is accepted; final acceptance additionally requires the live read-only probe.

## Required contract

1. Add `t_invest` as a real `PriceSource` and migrate the DB `price_source` constraint. Never encode T-Invest as `moex`.
2. Persist immutable **snapshot-scoped provider-neutral provenance** for every applied quote, including at minimum:
   - provider;
   - provider instrument id;
   - optional provider venue id;
   - quote kind/raw value/raw basis where applicable;
   - normalized price kopecks;
   - actual `price_date`;
   - `fetched_at_utc`;
   - target/reporting snapshot identity;
   - freshness classification.
3. Historical provenance must not be reconstructed later from mutable current mapping.
4. Existing editable-month guard remains authoritative. Closed month may preview, never apply without explicit reopen.
5. Apply only explicit owner-selected eligible rows. `stale` requires explicit per-row selection; it is never selected by default.
6. Production apply eligibility is T-Invest only for 0.4. MOEX reference mappings and `unmapped/excluded/unsupported/ambiguous/unavailable/network_error/malformed_response` cannot apply.
7. Frontend proposed money is never authoritative; backend obtains/normalizes the quote and recomputes existing position financial metrics through backend source-of-truth paths. NKD remains unchanged.
8. **Preview/apply consistency guard:** owner must never silently receive a different quote than the one just approved. Request may carry an expected preview fingerprint/value/date/identity as an optimistic guard, but not as financial truth. If refreshed server quote differs materially from the approved preview, reject with a deterministic `preview_changed`/conflict outcome and require a new preview.
9. **Atomic selected-set apply:** selected rows are one top-level transaction. Do not call the existing per-row `update_position_snapshot()` commit loop. Stage/flush selected changes and commit once; any failure rolls back the selected set.
10. Mapping edits after apply never rewrite historical price/provenance.

## Regression matrix

At minimum:

- one OK apply;
- multi-row atomic apply;
- one selected row fails → zero selected writes;
- closed month rejected;
- stale unselected by default + explicit stale selection path;
- quote changed since preview → conflict/no write;
- wrong provider/status rejected;
- T-Invest `price_source` persisted correctly;
- provenance immutable after mapping change;
- NKD unchanged;
- monetary metrics recomputed by backend;
- no background/startup network.

These are **not R04-only fixes**. They already exist in `main`, so implementation must start from current `main`; after acceptance, relevant fixes are forward-ported `main → r04`.

### M03-01 — loopback-only bind

Reject runtime configuration that binds Hermes Finance to a non-loopback address. The product has no auth specifically because it is local-only; `HERMES_FINANCE_HOST=0.0.0.0` must not silently remove that trust boundary. Add Settings/CLI regression tests. Prefer completion before formal `v0.3.0` release.

Current candidate: `m03-01-loopback-bind` @ `31c40019404f3463f7c60e7b8ea889ffb09bd00d`; exact runtime test/CI verification remains pending before acceptance/integration.

### M03-02 — signed realized loss

A `realized_loss` event must not be persistable with positive signed `net_amount_kopecks`, because IIS/dashboard aggregate `net_amount_kopecks` as signed P&L. Define one authoritative write invariant and regression tests without double-negating already signed values. Prefer completion before formal `v0.3.0` release because this is financial correctness.

Current candidate: `m03-02-realized-loss-sign` @ `5361efcd1c40714b040c0062d07cbeb44cafeb98`; exact runtime test/CI verification remains pending before acceptance/integration.

### M03-03 — multiple salary rows

Frontend currently edits/displays the first SALARY row while backend tax/cash services intentionally sum all SALARY rows for the month. Either make SALARY cardinality authoritative (one row per month) or make UI represent/edit the full aggregate without hiding rows. This is real consistency debt but does not block R04-06.
