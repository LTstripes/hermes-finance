# Hermes/Codex — последовательный backlog

> **Статус:** MVP `0.1.0` завершён; этот пошаговый backlog **заморожен как исторический план строительства MVP**.  
> Новые post-MVP задачи ведутся в активных release-файлах, начиная с `docs/RELEASE_0_2.md`.  
> Legacy-разделы H/I/J/K ниже сохраняются как roadmap/reference и **не являются активным scope релиза автоматически**: задача из них сначала должна быть явно перенесена в соответствующий release backlog как task-card.

**Правило:** одна задача за одну итерацию.  
**Главная спецификация:** `docs/MASTER_SPEC.md`  
**Приватные данные:** только локально, не в Git.  

---

## 0. Общие правила выполнения задач

Для каждой задачи Hermes должен:

1. Прочитать описание задачи и связанные разделы мастер-спецификации.
2. До изменений кратко описать план.
3. Не расширять scope «заодно».
4. Добавить или обновить тесты, если меняется логика.
5. Запустить минимально достаточные проверки.
6. Отчитаться по шаблону из `HERMES_START_PROMPT.md`.
7. Не начинать следующую задачу автоматически.

### Definition of Done для любой задачи

- код запускается;
- тесты задачи проходят;
- нет персональных данных в Git;
- документация обновлена, если изменён публичный контракт;
- изменение маленькое и проверяемое;
- не нарушены решения из раздела 18 мастер-спецификации.

## Post-B19 remediation gate

Архитектурный checkpoint Sol High после B19 выявил блокеры расчётного слоя. До C01 последовательно выполнить две bounded remediation-итерации. Они исправляют принятые инварианты и не разрешают общий rewrite B-слоя.

### B19-R1. Стабилизировать валютный контракт RUB-агрегатов

**Цель:** исключить арифметику между суммами разных валют без явной RUB-оценки.

**Сделать:**

- сохранить исходную сумму и ISO currency;
- для каждой non-RUB суммы, участвующей в C01/C02/C04, хранить явную ручную RUB-оценку, дату оценки и источник;
- не интерпретировать foreign minor units как копейки RUB;
- агрегаторы должны fail closed и возвращать warning, если обязательная RUB-оценка отсутствует;
- миграция не должна терять или молча переинтерпретировать существующие значения;
- покрыть cash, позиции и фактические/ожидаемые денежные потоки; явно решить контракт депозитов, если non-RUB депозит разрешён.

**Приёмка:** синтетические `100 RUB + 100 USD` никогда не дают `200 RUB`; запись без RUB-оценки не попадает в итог молча.

**Route:** Terra High primary / Luna High bounded worker / Terra High reviewer. Sol подключается только при новом конфликте контракта или destructive migration semantics.

---

### B19-R2. Усилить инварианты месяца, кэшбэка и основной цели

**Цель:** закрыть обходы уже принятых бизнес-правил до расчётного слоя.

**Сделать:**

- единый guard редактируемого отчётного месяца для create/update/delete всех month-scoped сущностей;
- закрытый месяц меняется только после явного `reopen`;
- при смене `income_type` на `cashback` passive-income flag всегда становится `false`;
- `goals` является runtime source of truth основной цели; значение в `app_settings` служит seed/default;
- существующий settings API при изменении passive-income target согласованно и транзакционно обновляет main goal; независимое конкурирующее runtime-значение в settings запрещено;
- добавить regression-тесты на все три воспроизведённых обхода;
- не реализовывать B19-R1 мультивалютный контракт: решение владельца от 2026-08-07 — B19-R1 deferred, RUB-only режим остаётся базовым.

**Приёмка:** дочернюю запись закрытого месяца нельзя создать/изменить/удалить; cashback не становится passive income через update; C05 видит единственное актуальное значение цели.

**Route:** DeepSeek V4 Flash primary / без worker / GLM 5.2 reviewer.

# Фаза C. Расчётный слой

> **Launch condition:** C01 начинается после приёмки B19-R2. B19-R1 (мультивалютный контракт) deferred решением владельца от 2026-08-07: RUB-only режим не требует валютного gate; при появлении non-RUB входных данных контракт возобновляется из `git stash`. Расчёты реализуются как pure domain functions/DTO без зависимости от SQLAlchemy, FastAPI или React; ORM application service отвечает только за выборку и mapping.

## C01. Рассчитать ликвидный капитал

**Цель:** единый доменный сервис капитала.

**Сделать:**

**Приёмка:** недвижимость не попадает в результат.
