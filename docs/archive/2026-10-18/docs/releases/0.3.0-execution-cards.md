# R03-08 — Review / close / reopen + closeout decomposition

**Executor:** Hermes  
**Reviewer:** Лера  
**Priority:** P0  
**Dependencies:** R03-06, R03-07 accepted/integrated.  
**Current started baseline (2026-08-12):** `97d247c5749c892f04373ab08b26578a28ba8934`. Если `r03-08-review-closeout` уже существует от этого baseline — продолжить её, не пересоздавать.

## Goal

Превратить legacy closeout-блок в ясный lifecycle flow: пользователь редактирует месяц в workspace, отдельно запускает проверку, осознанно закрывает месяц, а закрытый месяц при необходимости явно reopen-ит. IIS/Goals/comments не должны выглядеть обязательными частями процедуры закрытия.

## Required scope

### Review flow

`Проверить и закрыть` открывает focused review surface — dialog, drawer или эквивалент, если он лучше вписывается в existing shared UI.

На первом уровне review показать:

- месяц и статус;
- concise KPI preview, достаточный для проверки перед close;
- blockers, при которых close нельзя выполнить;
- warnings, требующие решения пользователя;
- короткий readiness/checklist state;
- main passive-income goal только как informational summary/link, без отдельного редактора;
- одну явную primary action `Закрыть месяц`.

Informational/technical warnings, не требующие решения, увести в details/help и не смешивать с blockers.

### Close / reopen

- сохранить существующий explicit backend close contract;
- никаких auto-close или close вслед за Save;
- закрытый месяц остаётся immutable до explicit reopen;
- CLOSED presentation read-only;
- `Открыть для редактирования` / reopen — явное secondary действие;
- после reopen месяц снова editable, но не получает silent mutations сам по себе.

### MonthCloseoutSection decomposition

Legacy `MonthCloseoutSection` больше не должен быть контейнером всего подряд.

- lifecycle close/reopen → review/lifecycle flow;
- legacy Main Goal editor/fragment → удалить из closeout; Goals остаётся canonical source of truth;
- устаревший warning про отсутствующий `/api/goals` → удалить;
- comments → представить как `Заметка месяца` в естественном month context, не как обязательный этап закрытия;
- IIS profile/contributions/benefits → вынести из closeout в существующий account/IIS context, если это возможно без новой финансовой семантики;
- если relocation IIS реально требует новой persisted сущности, новой tax semantics или нового contract — STOP с blocker, не придумывать это внутри R03-08.

## Must preserve

- financial formulas;
- close/reopen API semantics;
- closed-month immutability;
- Goals source of truth;
- IIS/tax semantics;
- unsaved/local draft guarantees R03-06/R03-07;
- отсутствие silent saves.

## Explicitly out of scope

- R03-10 copy/state cleanup beyond strings directly touched by closeout;
- R03-14 global polish;
- R03-17 passive-income eligibility;
- новая финансовая формула;
- широкая перестройка Accounts/Goals.

## Verification

Frontend minimum:

- targeted `MonthDetailPage` / lifecycle / review tests;
- full `npm test`;
- `npm run lint`;
- `npm run build`;
- `git diff --check`.

Backend if touched:

- targeted close/reopen tests;
- broader backend suite proportional to change;
- exact-money/privacy invariants unchanged.

Real Windows browser smoke, synthetic data only:

- `1366×768`;
- `1024×768`;
- `760×768`.

Scenarios:

1. DRAFT → edit/save → review → warnings/blockers → explicit close.
2. CLOSED → read-only → explicit reopen → editable.
3. Escape/focus return/outside-click for review surface.
4. Sticky lifecycle controls do not cover content.
5. No horizontal overflow/action collisions.
6. Month note remains accessible.
7. Legacy Goal closeout fragment absent.
8. IIS no longer visually reads as mandatory close step.
9. Navigation/review produces no silent mutation requests.

## Delivery

Preferred branch: `r03-08-review-closeout`.

After green verification:

- normal commit;
- push only `origin/r03-08-review-closeout`;
- no merge / no PR;
- final report: exact remote HEAD, changed files, tests/lint/build, smoke matrix, git status, known limitation if any;
- STOP. R03-17/R03-10 не начинать.

# R03-17 — Passive-income history eligibility implementation

**Executor:** Hermes  
**Reviewer:** Лера  
**Priority:** P0  
**Dependency:** accepted R03-16 / ADR 0008 **must already be integrated into baseline**. Если нет — STOP; не cherry-pick contract самостоятельно без owner instruction.

## Goal

Дать владельцу одну явную настройку начала полной passive-income history, чтобы ранние технические salary/tax months не искажали historical passive-income average, но реальные нулевые месяцы после границы продолжали честно входить в среднее.

## Normative semantics

Следовать ADR 0008, не интерпретировать заново:

- persisted logical setting `passive_income_history_start_month: YYYY-MM | null`;
- user label: `Учитывать пассивный доход начиная с`;
- boundary inclusive;
- `null` = legacy all-history behavior;
- existing DB migration → `null`, никаких inferred owner-specific dates;
- new DB default → `null`;
- eligible historical month = CLOSED + on/after boundary;
- eligible zero/negative month входит;
- DRAFT/reopened не входит;
- missing calendar month не становится synthetic zero;
- rolling window = последние 12 eligible CLOSED records, не calendar year;
- frontend не фильтрует и не считает average самостоятельно.

## Backend/storage

- добавить persisted setting минимально и versioned migration;
- migration backward-safe, не переписывает reporting months;
- один shared backend eligibility selector/source;
- C03 actual passive-income average использует его до last-12 calculation;
- passive-income Goal current/progress наследует тот же C03 source, без второго фильтра;
- C04 actual-dividend history component использует ту же boundary;
- forward-looking expected coupon/interest/other cash flows boundary не фильтрует;
- exact money / Decimal / ROUND_HALF_UP preserved.

## API/UI

- settings API read/write поддерживает boundary в однозначном `YYYY-MM | null` contract;
- UI control разместить в Settings/analytics-related settings там, где не смешивается с month input;
- изменение boundary требует explicit save/action, никаких silent writes;
- `Сбросить`/clear возвращает `null` legacy behavior;
- Dashboard/Goals/passive help показывает фактически использованный count/window достаточно кратко;
- не создавать per-month exclusion checkboxes.

## Required regression examples

Synthetic tests минимум:

1. pre-boundary CLOSED non-zero → excluded;
2. boundary month CLOSED zero → included as zero;
3. eligible negative month → included;
4. DRAFT after boundary → excluded;
5. CLOSED → reopen → excluded → reclose → included;
6. missing calendar month → no denominator slot;
7. `<12` eligible CLOSED → divide by actual eligible count;
8. `>12` → latest 12 eligible records only;
9. `null` reproduces pre-R03-17 result;
10. Goal current/progress matches filtered C03 source;
11. dividend forecast component uses same boundary while expected forward flows remain unchanged;
12. clear boundary restores all-history eligibility.

## Verification

Backend:

- migration upgrade from existing synthetic previous-head DB;
- migration on new DB;
- targeted passive average / settings / goal / forecast tests;
- full `pytest`;
- `ruff check`;
- `ruff format --check`;
- migration/readiness startup path if affected.

Frontend:

- targeted Settings + Dashboard/Goals presentation tests;
- full `npm test`;
- lint;
- build;
- `git diff --check`.

Windows smoke with disposable DB:

- 1366/1024 at minimum, 760 if touched presentation requires it;
- default `null` keeps legacy value;
- set boundary → visible average/count changes as expected;
- eligible zero month remains counted;
- clear boundary restores old window;
- restart app → persisted setting survives;
- working DB is not used for synthetic verification.

## Out of scope

- arbitrary month selection/exclusion list;
- redefining what passive income is inside a month;
- changing expected-cash-flow provenance;
- calendar-year averaging;
- editing historical reporting-month data to emulate the setting.

## Delivery

Preferred branch: `r03-17-passive-income-eligibility`.

Commit + push task branch only; no merge/PR. Final remote HEAD + checks + migration/smoke result + clean status. STOP.

# R03-10 — Progressive help / technical-copy / state consistency pass

**Executor:** Hermes  
**Reviewer:** Лера  
**Priority:** P1  
**Dependencies:** R03-08 and R03-17 integrated; main redesigned flows should be structurally stable before this pass.

## Goal

Убрать техническую и методологическую шумность из первого уровня UI, не потеряв важные caveats. Сделать empty/error/warning/locked/success states одинаково понятными по всему приложению.

## Scope

Audit main user flows:

- Dashboard;
- Analytics;
- Months;
- Month workspace/review;
- Goals;
- Accounts & Instruments;
- Settings/Diagnostics;
- Export/backups where relevant.

### Technical copy cleanup

С первого уровня убрать или перевести в help/details:

- `backend` как пользовательское объяснение;
- endpoint/API names;
- storage/internal enum names;
- `MASTER_SPEC §...` references;
- calculation/version internals вне Diagnostics;
- длинные методологические абзацы, если пользователь может сначала увидеть concise interpretation;
- остаточные placeholder/MVP/implementation labels.

Не удалять финансовый caveat, если без него цифру можно понять неправильно. Такой caveat → concise visible text или `ⓘ`/`Подробнее` согласно риску.

### State model

Привести к единому поведению:

- Error → persistent, action/recovery where possible;
- action-required Warning → persistent amber;
- incomplete-but-valid → muted badge/help, не красная тревога;
- Empty → короткое объяснение + максимум один primary CTA;
- Closed/locked → status + clear reopen action, не длинная простыня;
- Success → compact/transient where supported;
- technical runtime diagnostics → Settings/Diagnostics.

### Passive-income copy

После R03-17 wording должен однозначно говорить rolling semantics: `N закрытых месяцев из 12`, boundary/start period when useful; не называть это calendar-year average.

## Out of scope

- финансовые формулы;
- новая навигация;
- крупный visual redesign;
- R03-14 spacing/table redesign;
- новые backend contracts без blocker.

## Verification

- targeted tests для изменённых interactive states;
- full frontend test/lint/build;
- `git diff --check`;
- deliberate source search по запрещённым user-facing technical strings с documented intentional exceptions;
- Windows visual smoke 1366/1024 на основных screens + 760 для states/controls, которые менялись;
- keyboard/focus для help/details/dialogs, если затронуты.

## Delivery

Preferred branch: `r03-10-copy-states`.

Commit + push task branch only; no merge/PR. Report exact HEAD, intentional technical-string exceptions, checks/smoke, clean status. STOP.

# R03-14 — Cross-app responsive / accessibility / owner visual polish

**Executor:** Hermes  
**Reviewer:** Лера + owner visual look  
**Priority:** P1  
**Dependencies:** R03-08, R03-17, R03-10 integrated. Это финальный visual pass, поэтому не начинать его на промежуточной структуре экранов.

## Goal

Сделать текущий 0.3 UI одной визуальной системой и закрыть owner-visible проблемы, а не добавлять новые функции.

## Mandatory owner-review follow-ups

### R03-14A — numeric formatting

Cross-app audit display-money/quantities:

- RUB display группирует разряды: `123 456 ₽`, не `123456 ₽`;
- использовать shared formatter;
- проверить cards, badges, table cells, totals, tooltips, chart labels, Goals, Dashboard, Analytics, Month, Accounts, Settings;
- editable raw inputs не форматировать способом, ломающим cursor/parsing;
- presentation-only, без новой financial math.

### R03-14B — Month / Positions density

- `price_date` сохраняется в contract;
- если дата цены = month snapshot date, не занимать ей отдельную шумную первичную колонку;
- отличающаяся дата и `price_source` остаются видимыми secondary detail;
- `Средняя стоимость` в UI назвать/объяснить как `Средняя цена приобретения` за единицу;
- market value/cost basis/unrealized result остаются backend-derived;
- одна видимая action `Изменить`; destructive delete → overflow + confirm;
- НКД/metadata доступны, но не раздувают каждую строку;
- на 1366/1024 нет тесноты, 760 имеет аккуратный fallback.

### R03-14C — Debts / Property density

- убрать широкую постоянную конкуренцию `В ликвидном капитале`; compact state/detail;
- delete → overflow/compact destructive pattern;
- debt/property amounts не сталкиваются с actions;
- debt/property financial/include semantics не менять.

### R03-14D — Goals width

- одиночная/небольшая группа secondary goals использует доступную ширину;
- `Сейчас / Цель / Осталось` не ломает большие суммы на уродливые переносы при достаточном viewport;
- сохранить main-vs-secondary hierarchy;
- 760 → аккуратная одна колонка.

## Full responsive matrix

Обязательно пройти:

- Dashboard;
- Analytics;
- Months;
- Month workspace + review;
- Goals;
- Accounts & Instruments;
- Settings;
- Export/backups if they use shared layout.

Viewports:

- wide desktop;
- `1366×768`;
- `1024×768`;
- `760×768` fallback.

Rules:

- secondary columns/details collapse before actions become unreadable;
- horizontal page overflow absent at supported widths;
- local table scroll only when genuinely unavoidable and never as accidental result of menu open;
- popovers/overflow menus are not clipped and do not resize rows/cards;
- dialogs/drawers remain inside viewport;
- sticky headers do not cover content;
- typography avoids accidental tiny text / unreadable uppercase;
- Analytics may use wider canvas than ordinary form pages.

## Accessibility / interaction

- keyboard reachability of primary actions, tabs, menus, dialogs;
- visible focus;
- Escape closes modal/menu and returns focus appropriately;
- destructive actions separated and confirmed where existing contract requires;
- labels/accessible names preserved;
- no hover-only critical information.

## Out of scope

- new feature/metric;
- formula changes;
- broad backend refactor;
- new design-system dependency;
- brand/theme redesign.

## Verification

- targeted tests for touched interactive components;
- full frontend suite;
- lint/build/diff check;
- backend only if unexpectedly touched — if semantics would be affected, STOP rather than expand scope;
- real Windows Chromium visual/interaction smoke on full matrix;
- synthetic screenshots only, not committed;
- explicitly inspect owner issues: numeric spacing, Positions, Debts/Property, Goals width.
