# Hermes Finance UI v2 — месячное рабочее пространство

**Статус:** предложение архитектуры и локально проверенный кандидат S01, не принятый релиз.
Финальная запись кода в GitHub заблокирована инструментом; PR содержит раннюю версию.
Локальный UI v2 browser QA не выполнен из-за политики среды; новый remote browser QA
остаётся незавершённым. Подробности и точные границы доказательств — в DELIVERY.md пакета.
Задача: [#377](https://github.com/LTstripes/hermes-finance/issues/377).
Кандидат: [draft PR #378](https://github.com/LTstripes/hermes-finance/pull/378),
`feat/377-ui-v2-month-workspace`.
Исследовательский baseline: `a06e1fb58cc77b6bd2c4db8ca7cfd3e870df9c18`, 14 сентября 2026.
Независимое архитектурное ревью и owner UAT обязательны перед принятием/переключением.
Самопроверки автора не являются независимым ревью.

## 1. Продукт, который мы сохраняем

Это не торговый терминал и не ежедневный трекер покупок. Основная работа — раз в месяц
собрать достоверный снимок личных финансов, понять результат и следующие события,
исправить исключения и явно зафиксировать месяц. Windows, один пользователь,
локальная SQLite и loopback — преимущества этого сценария, а не пробелы дизайна.

Система уже существенно больше простого dashboard: отдельные фактические и будущие
потоки, чистый ликвидный капитал, долги и недвижимость, история доходности,
провайдерские предпросмотры, сверка, происхождение данных, закрытие и резервные копии.
UI v2 меняет способ доступа к этим возможностям, а не финансовую модель.

## 3. Целевая концепция и information architecture

**«Мой месяц»: что получилось → что требует внимания → что делать дальше.**

Отчётный месяц всегда виден. Дата снимка отдельно: это дата оценки, а не другое
название периода. При переключении, повторной проверке и ошибке старые суммы
не показываются как новые. Нулевая сумма остаётся нулём, неизвестная — неизвестной.

Целевая навигация группирует задачи, а не провайдеров и таблицы:

| Область v2 | Пользовательский вопрос | Существующие возможности, которые должны сохраниться |
| --- | --- | --- |
| **Мой месяц** | Что сейчас важно и как завершить месяц? | Выбор/создание/копирование периода, snapshot date, guided close, readiness, freshness, ручной финальный обзор, явный close/reopen, комментарии, следующий месяц |
| **Капитал** | Что у меня есть, кому должен и где риск? | Cash, депозиты, ценные бумаги, счета/инструменты, долги, APR/сроки/платежи, недвижимость/ипотека, связанные активы и обязательства gross/liability/net, allocation/concentration и контекстная сверка |
| **Доход и планы** | Что получил и на что могу рассчитывать? | Фактический passive income, среднее закрытой истории, датированные выплаты и возврат principal отдельно, прогноз 12 месяцев, зарплата/НДФЛ, ИИС, обязательные расходы, отдельно planned budget, savings/goals, налоги и существующий single-shock scenario lab |
| **История и результаты** | Почему изменился капитал и какова доходность? | Архив, сравнение месяцев, historical dynamics, value bridge, XIRR/TWRR с честной доступностью и ограничениями; изменение капитала не называется доходностью |
| **Данные и приложение** — вторичная область | Откуда данные и как их сохранить? | Явные provider/import previews и mappings, настройки, происхождение данных, runtime diagnostics, backup/restore, Markdown/JSON/export, ручной AI analysis/review export без автоматической отправки в облако |

AI review и экспорт конкретного месяца также доступны из его контекста, а не только
из системного раздела. Неизложенные пока в UI deterministic insights остаются отдельной
возможностью backend: нет обещания автоматически построенного советника или новых правил.
Исторические инструменты и справочники не превращаются в month-local дубликаты.

Это целевая карта, не список уже созданных экранов. S01 показывает только настоящий
native пункт «Мой месяц»; остальные ссылки явно помечены «В текущем интерфейсе».
Неработающих tabs, фиктивных графиков, тестовых чисел в продукте и будущих кнопок нет.

### Основной путь

Открыть/скопировать месяц → проверить дату снимка → выполнить применимые явные
провайдерские и импортные шаги в порядке существующего workflow → проверить
расхождения и исключения → подтвердить/исправить ручные значения в финальном обзоре
→ понять результат и предупреждения → явно закрыть → посмотреть известные события
следующего месяца.

Порядок не задаётся новым frontend списком правил. Server recommendation определяет
следующее действие; владелец может осознанно выбрать другой шаг, а его допустимость
проверяет существующий сценарий/backend. Провайдер может быть недоступен — это не
разрешение подставить нули, применить старые котировки или заблокировать другие шаги
сверх backend contract. Закрытый месяц открывается для просмотра, не для скрытого reopen.

Визуально: светлая нейтральная поверхность, один синий акцент, сильная типографическая
иерархия, спокойная карточка действия, текстовые статусы и native disclosure. Зелёный
не используется как декоративное обещание успешности финансов: MASTER_SPEC §12.1.
Это рабочая дизайн-гипотеза, которую можно изменить без изменений данных.

## 4. Безопасное сосуществование

**Выбор:** один React/Vite build, существующий Router/QueryClient и backend;
отдельный лениво загружаемый sibling route `/v2`, CSS Modules и локальная error boundary.
V1 остаётся на прежних адресах и остаётся default. `/v2?month=12&step=market_quotes`
однозначно задаёт контекст. Bare `/v2` закрепляет последний календарный месяц через
replace URL; не выбирает самый большой ID и не заменяет явно неверный месяц.

Почему не отдельный frontend/runtime: второй build, общий launcher и распределение
API внесли бы эксплуатационную сложность без ценности для одного локального пользователя.
Почему не глобальный restyle: CSS и поведение старых страниц менялись бы до UAT.
Почему не BFF/новый workflow API: нужный read model уже существует.

S01 читает только GET `/api/health`, `/api/months`, `/api/months/{id}/close-workflow`.
Последний включает готовность, показатели и рекомендацию. Фокус, раскрытие деталей,
выбор шага и периода не вызывают provider requests или mutations. Нет localStorage
с прогрессом, второго финансового расчёта или телеметрии. Идентичность верхнего месяца,
вложенного final review и версия контракта проверяются перед отображением результатов.

Изменения затрагивают только frontend, дизайн-документ и синтетический PR evidence job.
Backend, DTO, persistence, migrations, зависимости/lockfile, launcher и release identity
не меняются. Существующий SPA fallback обслуживает `/v2`; новый endpoint не нужен.

Переход в v1 идёт на существующий month-specific route с hash нужного шага. Это
**явный handoff, не завершённый native wizard**. Browser Back возвращает URL v2;
повторный mount перечитывает сохранённый результат. Вспомогательные ссылки в v1
сохраняют его правила выбора месяца, о чём сказано в оболочке. S01 не меняет их молча.

### Rollback

До cutover достаточно пользоваться v1; нет миграции пользовательских данных.
Для удаления кандидата убираются route/import, opt-in ссылка и изолированные v2 файлы.
Если CSS/chunk/page v2 не загрузился, остаётся ссылка на текущий интерфейс.

**Это UI rollback на том же backend baseline, а не downgrade базы.** Уже существующие
изменения dev main относительно опубликованного Stable никуда не исчезают.
Нельзя направлять новый dev backend на личную Stable БД ради просмотра дизайна.
Разработка/CI используют только синтетические fixtures. Позднейший owner UAT — в
подготовленном отдельном runtime по ADR 0012/0014, не в agent workspace.

## 5. Небольшие вертикальные этапы

| Срез | Рабочий результат и проверка | Граница / обратимость |
| --- | --- | --- |
| **S01 — этот кандидат** | Native «Мой месяц»: период, три итоговых показателя, readiness, причина следующего действия, список server steps, labelled v1 handoff; состояния и browser QA | Только чтение. V1 default. Не утверждаем, что весь месячный цикл уже ускорен |
| **S02 — ручная коррекция в финальном обзоре** | На том же месяце открыть текущие денежные остатки, исправить одну строку существующим cash API, явно сохранить, увидеть пересчитанные сервером KPI/readiness и вернуться в обзор | Сначала один тип ручных данных, не весь редактор; existing closed-month guard, ошибки/unsaved state/повторное чтение. Проверка ближе к финалу, не новый ранний обязательный шаг |
| **S03 — один provider/import путь за раз** | Сначала выбранный существующий Alfa baseline или payout-import: preview → видимый scope/mapping → явное apply → обновлённый месяц | Переиспользовать accepted contracts; никакого mount-time fetch/apply, одинаковые privacy и selected-row guarantees |
| **S04 — native final close и outlook** | Полный компактный итог, ручные карточки по мере готовности, свежая readiness, explicit close, view-only closed state и известные будущие события | Не менять обязательные блокеры и race rechecks; close/reopen и UAT — отдельные acceptance gates |
| **S05 — капитал, планы и история** | Переносить законченные задачи с drill-down и одинаковыми backend числами; включить risk, tax/IIS, linked financing, return availability и export | Capability parity по таблице выше; v1 escape до приёмки каждой области |
| **S06 — cutover** | Owner сравнительный UAT, проверка всех привычных операций и controlled default switch | Только явное approval. Удаление v1 — отдельное решение после периода успешного использования |

Зависимости: S01 → S02; затем последовательно принять общие interaction patterns до
параллельного переноса областей. Не строить отдельную большую design-system библиотеку,
общую state-machine платформу и новые API «на будущее». Признак лишней сложности —
когда поддержка оболочки дороже следующей законченной пользовательской операции.

## 6. Как сравниваем с v1

Одинаковый синтетический период/факты и заранее записанные задачи. Время владельца
замеряется только на UAT; следующие числа — **целевые критерии, не результаты**.

| Задача / риск | Проверка / цель |
| --- | --- |
| Понять выбранный месяц, snapshot и следующее действие | Верные ответы без открытия другого раздела; ориентир до 15 секунд |
| Отличить текущий факт, прогноз и изменение капитала | Владелец правильно объясняет все три; прогноз не принимается за следующую выплату |
| Найти обязательные исправления | Не путаются warnings и blockers; одинаковые can_close/counts с API |
| Вернуться из операции | Тот же period/step, без ручного поиска; новый запрос свежих результатов |
| Переключить период при медленном ответе | Ни одного кадра с суммами прошлого периода под новым выбранным месяцем |
| Нет данных / ошибка / настоящий ноль | Разные видимые состояния; ошибку можно повторить; нет фальшивых нулей |
| Сохранность значений | UI выводит существующие exact money strings через общий formatter; без Number/float финансовых вычислений |
| Безопасность | Ноль implicit mutations/provider calls в S01; старые close/import paths неизменны |
| Компоновка | 1366×768, 1440×900, 1920×1080 и 390×844: нет горизонтального page overflow/обрезанных действий; крупные суммы и длинные подписи остаются читаемыми |
| Доступность | Один h1, keyboard/skip link, labelled select, видимый фокус, actionable panel после перехода, статусы не только цветом |
| Сложность месячного ритуала | Сравнить число переходов и повторных выборов периода после S02–S04; S01 handoff не выдаётся за их устранение |

Browser screenshots проверяют компоновку, а не финансовую корректность сами по себе.
Типизированные fixtures и component tests проверяют выбранные состояния; независимое
ревью сравнивает их с реальным DTO и backend source. Существующий v1 UAT не переносится
автоматически на новую оболочку.

## 7. Воспроизводимость S01 и следующий gate

Синтетические данные: `frontend/src/test/uiV2Fixtures.ts` (2031 год, вымышленные суммы).
Runtime code не импортирует fixture. Новые тесты живут в существующих page/lib/e2e lanes.

```sh
cd frontend
npm ci
npm test -- src/pages/UiV2Page.test.tsx src/lib/uiV2MonthSelection.test.ts
npm run lint
npm run format-check
npm test
npm run build
npx playwright install --with-deps chromium
npm run audit:visual -- --grep ui-v2
```

Новый `.github/workflows/ui-v2-evidence.yml` сохраняет только синтетические PNG,
публичный frontend build и provenance exact source SHA, retention 7 дней.
Он не получает личную БД/токены провайдеров и не меняет основной CI workflow.
Временный bootstrap передачи публичного source/dependencies использовался при
разработке в ограниченной среде; в локальном completion patch он удалён.
В раннем remote candidate 34d75a5 он пока остаётся: PR нельзя принимать в таком состоянии.

В среде автора системный Chromium блокирует loopback navigation
(`ERR_BLOCKED_BY_ADMINISTRATOR`); этот локальный browser run не является PASS.
Для завершения нужен browser evidence в изолированном GitHub Actions,
затем скачивание screenshots и визуальная проверка. Для финального UI v2 этот этап
не завершён: code-write был отклонён safety-проверкой инструмента. Локальные component/lint/build
проверки и remote Chromium evidence указываются раздельно. Private/Windows live UAT
не выполняется автором вместо владельца.

Перед принятием: независимое ревью target IA/контрактов/реального diff; затем owner
оценка стартового экрана на безопасном Preview. Решения владельца — соответствует ли
ежемесячный главный экран его способу работы, какие ответы ещё нужны на первом плане,
и когда переключать default/выводить v1. CSS framework, путь `/v2` и детали обратимой
компоновки не требуют отдельного owner выбора.
