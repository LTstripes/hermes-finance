# Documentation index

The current handbook is five books. Start with the book that owns the question; do not copy status or rules into another book.

1. [Product and user journeys](MASTER_SPEC.md) — product scope, monthly workflows, screens, supported sources, goals and desktop UX.
2. [Architecture, financial semantics and contracts](ARCHITECTURE_AND_CONTRACTS.md) — architecture, formulas, source authority, API/export contracts and receipts.
3. [Development, verification and integration](DEVELOPMENT.md) — roles, workspaces, implementation discipline, review, delivery and optional client mechanics.
4. [Operations, release and recovery](OWNER_RUNTIME_OPERATIONS.md) — runtime roles, Prepare/Validate/Start, publication, backup/restore and retirement.
5. [Current state, limitations and next actions](CURRENT_STATUS.md) — the only changing status page.

Supporting collections:

- [ADRs](adr/) — durable architecture and financial decisions.
- [Release notes](release-notes/) and the [current 1.3.0 notes](release-notes-1.3.0.md). Release-note family files stay at the docs root because release identity checks read `docs/release-notes-X.Y.Z.md`.
- [1.4.0 draft notes](release-notes-1.4.0.md), its [Test-run checklist](releases/1.4.0-test-run.md) and [rollback plan](releases/1.4.0-rollback.md) — unpublished candidate preparation, not a release, financial result or UAT acceptance.
- [History](history/README.md) — dated receipts and retired process notes; not current instructions.
- [Evidence](evidence/839/README.md), [schemas](schemas/) and the [archive migration map](archive/2026-10-18/MIGRATION_MAP.md) — retained provenance.

Contributors start with [AGENTS](../AGENTS.md) and the assigned issue. [README](../README.md) describes the project; [CHANGELOG](../CHANGELOG.md) records released versions.
